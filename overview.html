Tokens

A macOS desktop app that answers one question: how much of my AI allowance have I burned, and how much is left? Click a topic to explore.

What it is

Everything is local — no accounts, no cloud sync, no telemetry.

Tokens watches the three agentic coding tools on this Mac — Cursor, Claude Code, and Codex — reads their local logs, normalizes everything into one canonical format, and shows the result in a dashboard window plus an always-on menu bar indicator.

Beyond historical totals, each source's live allowance window (the 5-hour Claude session, the 7-day week, the Cursor billing month) is polled continuously. When usage crosses a line you set, the app fires a macOS notification and offers to generate a handoff brief so work can move to another tool before the well runs dry.

The only network calls are to Cursor's own APIs, with the user's own credentials, for Cursor data only.

How data flows

discovery → source adapter → UsageRecordDraft → normalizer/validator
          → repository → Tauri command → React

Each stage fails independently — an unimplemented adapter, a file that vanished mid-scan, a malformed entry — and the per-source report says exactly what happened, with failures capped at 10 so a broken tree can't flood the UI.

Features

Click a feature to open it.

A dark, single-window UI reporting on a rolling 30-day window:

  • Stat bar — total tokens, input/output/cached/reasoning splits, cost when reported.
  • Source strip — one card per tool; click to filter the whole dashboard.
  • Model breakdown — usage grouped by model across all sources.
  • Event list — the most recent individual usage records, newest first.
  • Quota chips — e.g. claude code · 49% left this session, showing whichever window binds first.

Empty states distinguish "nothing imported yet" from "nothing matched the filter"; the footer reports records excluded from date-filtered views for unresolvable timestamps.

A status item showing the compact total plus one allowance chip per source: 302K · claude 49% · codex 63%.

When a source meters several windows at once (Claude runs a 5-hour session inside a 7-day week), the bar shows only the window that binds first — the number that decides whether you can keep working. The dropdown lists every window with reset times, plus totals and per-source breakdowns. It reads the same repository as the window, so the two can never disagree.

A quota is not a locally reconstructed total — it is the source's own statement of window consumption, freshest snapshot wins:

  • Claude Code — ~/.claude.json → cachedUsageUtilization: 5-hour session, 7-day week, per-model weekly caps where the plan has them.
  • Codex — rate_limits on token_count events; freshest across the 10 most recently modified rollout files.
  • Cursor — GetCurrentPeriodUsage on api2.cursor.sh (the endpoint Cursor's billing UI uses), with a local last-good cache when offline.

Polled every 60 seconds — much cheaper than a log import, so warnings stay timely.

Per-source thresholds in two flavors: remaining percent (warn at 25% left) or minutes until reset. On a crossing the app:

  • Fires a macOS notification with action buttons Generate handoff MD file / Continue (via notify-rust — Tauri's plugin doesn't forward actions on macOS).
  • Shows an in-app banner with the same actions.

Continue snoozes until the window resets. An in-process ledger dedupes (one notification per crossing per run) and prunes stale entries when windows reset or usage recovers.

When a tool is about to run dry, Create handoff copies a fixed prompt to the clipboard. Paste it into the still-alive agent and it writes .handoff/HANDOFF.md — goal, done so far, current state, next actions, do-nots, open questions — so work resumes in a different tool.

The prompt lives in the Rust domain (HANDOFF_PROMPT) and is served to React via a command, so both sides share exactly one string.

Cursor's local logs stopped carrying reliable token counts around January 2026. The fix: paste the WorkosCursorSessionToken cookie from cursor.com/dashboard in Settings. The app validates it against the real API, stores it in macOS Keychain, then rebuilds Cursor usage from get-filtered-usage-events — exact input, output, cache tokens, model, and billed cost for 30 days.

Disconnecting wipes the credential and falls back to incomplete local bubbles. Either change clears the store and re-imports everything.

Strict one-way layering — each layer depends only on the ones below it. Click a layer.

commands — the only surface React can call

15 Tauri commands, deliberately thin: accept a request, delegate, convert failures into AppError. No aggregation or parsing logic lives here. Also owns date-range validation (end must be after start).

state — what the running app holds

The repository behind its trait, freshest quota snapshots (account state, kept out of the usage store), user options + their path, and the alert ledger — all behind RwLock/Mutex for the background threads. Commands see the repository only through the trait, so swapping in SQLite touches this file and nothing else.

refresh · alerts · menubar · prefs — the runtime crew

refresh orchestrates one import pass per adapter with per-stage failure isolation, and the cheap quotas-only poll. alerts owns delivery: the fired/snoozed ledger, OS notifications with action buttons, and the threshold-alerts event. menubar repaints the tray after every import and poll. prefs persists options.json atomically (temp file + rename).

pipeline — drafts in, stored records out

Joins normalizer to repository. Rejected drafts are reported, not raised: one malformed entry never discards the entries around it. The import report (inserted / duplicates skipped / rejected) reaches the UI in full.

repository — storage behind one trait

Idempotent insert_batch (re-importing the same log is a no-op), summary, recent, count, clear. In-memory today; the deliberately narrow trait is what lets a SQLite backend replace it without touching the layers above.

normalize — the only producer of valid records

A pure function (clock injected) that validates drafts, computes SHA-256 dedupe keys and record IDs, resolves timestamps, and stamps imported_at. Everything downstream — repository, commands, React — assumes the invariants checked here already hold.

adapters — one per source, drafts only

Turn each tool's logs into UsageRecordDrafts. An adapter never validates, deduplicates, or stores, and never knows about other sources — that isolation is what lets one malformed log fail without affecting the rest. Filesystem paths stay inside the adapter behind opaque source_ref handles.

domain — shared vocabulary, depends on nothing

UsageRecord, TokenField, Money, UsageQuota, AppOptions, threshold alert evaluation, and the HANDOFF_PROMPT. Every other layer points here; it points nowhere.

Frontend structure

  • src/domain/usage.ts — TypeScript mirroring the Rust domain; changed only alongside the Rust types.
  • src/api/*.ts — the only modules that call invoke.
  • src/hooks/ — useUsageDashboard (data + refresh + event subscriptions, stale-request and unmount guards), useOptions, useThresholdAlerts.
  • src/components/ — StatBar, SourceStrip, ModelBreakdown, EventList, AlertBanner, SettingsView, AppMenu, Skeletons.
  • src/theme.ts — one hue per source on near-black; nothing else is colored, so color always means data.

Design decisions

The opinionated choices that make the app trustworthy. Click to open.

Every token category is a TokenField { value, quality } pair (exact / estimated / partial / unknown). A null means "not reported", never zero — totals mark themselves as lower bounds (unknownRecords > 0) instead of silently undercounting.

Amounts are integer minor units with currency and exponent ({ amount_minor, "USD", 6 } = micro-dollars); exponents up to 6 allow per-million-token pricing. All formatting — even in the menu bar — is integer arithmetic. Cost totals never mix currencies.

Keys are SHA-256 over the source's own event ID (or observable content when no ID exists), deliberately excluding adapter version and import time — upgrading an adapter can't resurrect imported records. The record ID derives from the key, so the same event always resolves to the same ID.

Clock passed in as a parameter. Zone-less timestamps read as UTC, not the Mac's local zone. An unparsable timestamp doesn't reject a record; date-filtered queries skip undated records and report how many were skipped.

Display totals prefer a source-reported total, else input + output (+ reasoning when reported). Cached input is excluded (sources report it as a component of input). Every total carries the rule that produced it, so the UI never guesses comparability.

Every snapshot carries observed_at; quota goes stale within minutes, so the UI can show age rather than pretend it's live. Percentages are integer tenths (930 = 93.0%), like money.

source_ref is an opaque adapter-owned handle; provenance records adapter id/version plus that handle — never filesystem paths, prompts, or responses.

Security & privacy

  • Cursor dashboard session token lives only in macOS Keychain (com.josep.tokens).
  • Cursor's local access token is read from state.vscdb, held in memory, sent only to api2.cursor.sh, never logged or cached.
  • The on-disk quota cache holds percentages and reset times only — no credentials.
  • Fully offline otherwise: no analytics, no external calls beyond Cursor's own APIs for Cursor data.

Startup & runtime

  • Load options.json (defaults: warn at 25% remaining on every source).
  • Request notification permission up front so the first crossing can notify.
  • Initial import runs on a background thread — hundreds of MB of logs, too slow to block the window; the UI fills in when usage-imported lands.
  • A 60-second quota loop: refresh → emit quotas-updated → repaint menu bar → evaluate alerts.

Usage records live in memory per process (re-imported on launch); options persist as JSON. The repository trait is the seam for a future SQLite backend.

Commands

The entire Tauri surface React can call. Click one.

usage_summary — totals and per-source/per-model breakdowns for the dashboard, filtered by source/model/date range.
recent_usage — the most recent usage records, newest first, same filters as the summary.
usage_record_count — total records in the store; lets the UI tell an empty store apart from a filter that matched nothing.
usage_sources — the three adapters with version and a readsLogs flag, so the dashboard can say "live" vs "soon".
usage_quota — the freshest quota snapshot per source; empty until the first refresh completes.
refresh_logs — the manual import: rescan every source, import what's new, repaint the tray, re-evaluate alerts. Per-source failures ride inside the report.
get_options — current user options (per-source thresholds).
set_options — normalize, validate, persist to options.json, replace in state, then re-evaluate alerts against the new lines.
cursor_connection_status — whether an authenticated Cursor dashboard session exists in Keychain.
connect_cursor_dashboard — validate the session token with a one-event probe, save it to Keychain, then clear the store and rebuild Cursor usage from authoritative remote events.
disconnect_cursor_dashboard — delete the credential, clear the store, and rebuild from local bubble data.
active_alerts — threshold crossings that are neither snoozed nor reset, for the in-app banner.
snooze_alert — the Continue action: silence this alert until its window resets.
handoff_prompt — the fixed prompt (shared Rust↔React) the UI copies to the clipboard for a HANDOFF.md brief.
test_notification — fire a sample OS notification so Settings can preview the alert look.
